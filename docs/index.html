01. Features

Every component is designed around two constraints: zero external dependencies and a 200 ms end-to-end budget.

📦
Zero Dependencies
The entire system runs on Python's standard library. No sentence-transformers, no FAISS, no spaCy. Dense embeddings are earned from the corpus itself via PPMI + random indexing — no checkpoint files to ship.
⏱️
200 ms Budget Enforcement
The orchestrator proactively sheds optional stages — query expansion, reranking, MMR diversification — before blowing the budget. Two-stage retrieval (sparse candidates → dense re-score) keeps cost proportional to candidate count, not corpus size.
🔍
Hybrid Retrieval
BM25 sparse search generates candidates. PPMI random-index dense embedder re-scores them. Scores fused with Reciprocal Rank Fusion. Optional cross-encoder rerank and MMR diversity pass.
✂️
7 Chunking Strategies
Fixed sliding window · Recursive structural splitting · Sentence window (±N neighbours) · Semantic drift-based boundaries · Proposition (atomic statements) · Metadata-aware · Hierarchical small-to-big. All run at index time; retrieval can filter by strategy.
🎙️
Voice Input
Real Sarvam AI and ElevenLabs STT clients with fallback chain. Browser Web Speech API as zero-key path — the demo works without any API key. ASR output is repaired against corpus vocabulary before retrieval.
🛡️
Full Guardrail Stack
Input: length check · safety classifier · injection detector · PII redactor · off-topic gate. Output: grounding overlap · entity support · number check · contradiction detector · confidence floor.
🌏
Script-Aware Tokenization
One tokenizer for all 10 languages. Classifies characters by Unicode script block — Devanagari, Bengali, Tamil, Telugu, Gujarati, Kannada, Malayalam, Punjabi, Oriya, Latin. CJK handled by unigram + bigram indexing. Danda (।) and double danda (॥) are recognized sentence terminators.
💬
Grounded Answer Generation
Extractive generator scores and selects sentence spans from retrieved chunks. Every sentence is cited to its source passage. LLM mode (Claude) available as opt-in enrichment, latency reported separately.
📊
Built-in Benchmarking
300-query latency harness with warmup, cold-cache mode, and percentile reporting (p50/p70/p90/p95/p99/p100). Circuit breakers, retry with exponential back-off + jitter, and full request tracing ring buffer.

🧮 Dense Embedder (no files)
Step 1 – Co-occurrence: Slide a window over the corpus, count term pairs.
Step 2 – PPMI: Convert raw counts to Positive PMI with Levy & Goldberg smoothing.
Step 3 – Random Indexing: Each term gets a seeded ternary hash signature. Embeddings = PPMI-weighted sum of context signatures. Johnson-Lindenstrauss projection, zero storage.
SIF removal: Subtract dominant corpus direction so short queries stop pointing at "generic prose".
⚡ Budget Shedding Logic
At 75% of the 200 ms budget, the orchestrator starts dropping optional stages in order of cost:

1. Query expansion (extra retrieval passes)
2. Cross-encoder reranking
3. MMR diversification

The mandatory path — embed → retrieve candidates → dense score → extractive generate — always runs. Optional enrichments only run if budget remains.

03. Quick Start

Get running in under 60 seconds with zero API keys.

1

Clone the repository

bash 
git clone https://github.com/gitofdhruvmishra/hhgoarag.git
cd hhgoarag
2

Run (no pip install!)

bash 
python3 run.py
# → Builds index from offline corpus (~5s first run)
# → Opens http://127.0.0.1:7860 in your browser
3

Optional: Add API keys for enhanced features

bash 
# Cloud speech-to-text (Sarvam AI)
export SARVAM_API_KEY=your_key_here

# ElevenLabs STT (alternative)
export ELEVENLABS_API_KEY=your_key_here

# Claude LLM for enriched answers
export ANTHROPIC_API_KEY=your_key_here

python3 run.py

💡 Without any keys, the browser's Web Speech API handles voice, and extractive generation produces answers — the full demo works.

4

Try some queries

examples 
English:  What is the capital of Maharashtra?
Hindi:    भारत में सबसे लंबी नदी कौन सी है?
Bengali:  বাংলাদেশের জাতীয় ফুল কী?
Tamil:    தமிழ்நாட்டின் தலைநகரம் எது?

06. Module Reference

Every module has a docstring explaining its design decisions. Here's the map.

vaani/textkit.py
Script-aware tokenizer · normalizer · sentence splitter · language detector · stemmer · entity extractor · query classifier · similarity helpers (Jaccard, overlap coefficient, token F1).
vaani/embed.py
PPMI co-occurrence matrix → random-index projection → unit-normalized vectors. All arithmetic via math.sumprod over array.array buffers (C speed). No files to ship.
vaani/config.py
9 nested dataclasses: Chunking · Retrieval · Generation · Guardrail · STT · Harness · Server · Dataset · Bench. Environment-variable overlay. Never errors on missing credentials.
vaani/harness/
orchestrator.py — Deadline tracker, stage runner, budget shedding, circuit breaker.
contracts.py — Typed data contracts for every stage boundary.
errors.py — Error taxonomy with retryable + degradable flags.
retry.py — Exponential back-off with jitter.
tracing.py — Ring-buffer trace store for the UI.
vaani/chunking/
7 strategies: fixed · recursive · sentence_window · semantic · proposition · metadata_aware · hierarchical. Near-duplicate collapse at 94% Jaccard threshold.
vaani/retrieval/
BM25 (k1=1.4, b=0.72) · dense scorer · RRF fusion (k=60) · cross-encoder reranker · MMR (λ=0.72) · query expansion · ASR repair against corpus vocabulary.
vaani/generation/
Extractive generator: score sentences against query, select top-N, add citations and exact quote spans. LLM generator: Claude API with grounding-aware prompt, latency measured separately.
vaani/guardrails/
Input rails: length · safety · injection · PII · off-topic coverage. Output rails: grounding overlap (>52%) · entity support (>72%) · number check · contradiction check · confidence floor (>30%).
vaani/stt/
Sarvam AI client (saarika:v2.5) · ElevenLabs client (scribe_v1) · browser Web Speech API bridge. Fallback chain: tries each in order based on key presence.
